# 回答朗读

`useSpeech` 管理一条消息的一次合成请求，`SpeechPlayback` 管理音频时间线。
音频请求经 `conversationAPI.textToSpeechStream` 和共享鉴权客户端发起；
读取二进制音频与 SSE 正文解析分别处理。

- 首次点击创建请求；加载期间再次点击只切换播放意图，不重复合成。
- 暂停保留当前位置与缓冲；后续音频到达不会自动恢复。继续朗读使用原音频。
- 自然播放结束后，点击朗读从头播放已有缓冲，不再次请求或追加整段音频。
- 开始另一条消息的朗读会暂停当前声音，避免多条回答叠加。
- 内容变化、停止或卸载时，撤销请求归属、取消读取、清空媒体源并释放对象 URL。
- 支持对应音频 MIME 的 MediaSource 浏览器边接收边播放；不支持时，收齐音频后
  交给原生 audio 解码。后者的首音延迟较长，不更换或伪装音频编码。

测试入口：`npx vitest run src/hooks/__tests__/use-speech.test.tsx`。
